# ClipSync · 剪剪相传

[![CI](https://github.com/fraternidaddeng/clipsync/actions/workflows/ci.yml/badge.svg)](https://github.com/fraternidaddeng/clipsync/actions/workflows/ci.yml)

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

**Windows と Android のあいだで動く、プライベートな P2P クリップボード同期ツール。** 片方の端末でコピーすれば、もう片方でそのまま貼り付けられます。テキストも画像も、暗号化された直接接続だけを通って自分の 2 台の端末間を移動します。アカウント不要、クラウドなし、中継サーバーなし、テレメトリーなし。

ペアリングは Bluetooth のように一度きり（QR コードをスキャンして証明書フィンガープリントを照合）。同期は LAN または Tailscale ネットワーク上で行われ、「できること・できないこと」を意図的に正直に伝える設計です — 特に Android のバックグラウンドでのクリップボード制限について。

> 利用できるビルドとチェックサムは [Releases](https://github.com/fraternidaddeng/clipsync/releases) を確認してください。このページは現在のソースツリーを説明し、未リリースの変更は [CHANGELOG](CHANGELOG.md) に記載します。

## 機能

### 同期

- **双方向同期と再接続後の追いつき。** 同期が許可され、保持期間内にあるキャプチャ済みコンテンツは再接続後に送信されます。重複とエコーは抑制され、ローカルのみの項目は再送しません。
- **テキストと画像。** 画像同期（プロトコル v2、チャンク転送、履歴にサムネイル表示）は 2026-08-28 以降**デフォルトで有効**。受信した画像を**ローカルのクリップボードへ自動適用する動作もデフォルトで有効**です。2 つの設定は互いに独立しており、いつでもオフにできます。1 MiB を超えるテキストはローカルにのみ保持され、黙って切り詰められることはありません。
- **両端末に履歴。** 検索可能な履歴、削除、保持上限（件数・期間）、エクスポート/インポート、機微なコピー元アプリの除外。
- **主導権はあなたに。** 同期の一時停止、プライベートモード、自動キャプチャの一時停止に加え、Android には「バックグラウンド同期サービス」のマスタースイッチがあります — オフにすれば本当に停止し、アプリの再起動や端末の再起動で勝手に復活しません。

### ペアリングと暗号化

- **QR ペアリング + フィンガープリント照合。** Windows が表示する QR コードに含まれるのはアドレス・ポート・証明書フィンガープリント・ワンタイムトークンだけで、**ペアリング秘密鍵は決して含まれません**。両画面に表示されるフィンガープリントを目視で照合し、双方で一度確認すれば完了です。
- **IP 接続は TLS 1.3 + 証明書フィンガープリント固定**。ペアごとの秘密鍵は Windows DPAPI と Android Keystore で保護され、ピン不一致時は接続を停止します。Bluetooth フォールバックは独自の認証付きチャネルを使います。
- **ローカルネットワークのみ。** 通信は LAN または Tailscale 上の直接接続だけ。クラウドデータベースも公開リレーも NAT 越えサービスもありません — 端末同士が到達できなければ同期しない、というのは設計上の境界であって不具合ではありません。
- **信頼はいつでも取り消せます。** どちらかの端末で相手を削除すれば即座に切断。相手のフィンガープリントが変わった場合（再インストールや機種変更）、Android では「確認済み — ペアリングを置き換える」の明示的な確認が必要です。

### Android のバックグラウンド読み取り — 正直な機能ラダー

Android 10 以降、通常のアプリはバックグラウンドでクリップボードを読めません。ClipSync は 3 つのバックグラウンド経路とフォアグラウンド / 手動入口を用意し、**経路**ページで正直に検出します。「読み取り」と「書き戻し」は別々に検出され、実際の読み取りテストに合格した経路だけが READY と表示されます。

| 段階 | 必要なもの | 特徴 |
|---|---|---|
| **特権直接読み取り** | ClipSync 内蔵の特権ホスト。PC から adb で起動コマンドを一度実行（USB または Android 11+ のワイヤレスデバッグ。Windows アプリならワンクリック） | 推奨ルート。オーバーレイポーリングを使わず、画面オフ時の動作は端末で確認します |
| **ログ検知 + オーバーレイ** | adb での `READ_LOGS` 付与（一度だけ）+ オーバーレイ権限 | コマンドはアプリ内からコピー可能 |
| **オーバーレイポーリング** | オーバーレイ権限のみ | PC 不要。電池消費と秒単位の遅延がコスト |
| **フォアグラウンド / 手動** | バックグラウンド読み取り権限は不要 | 他のアプリから共有し、受信項目は履歴からコピーできます |

権限は必要なときに付与でき、取り消しも可能です。使えない経路からは利用できる経路へ切り替わります。Windows の端末検出・特権起動・ワイヤレスのペアリングと接続では adb を使います。ワイヤレスペアリングの QR 表示中だけ最大 2 分間デバイス検出を行い、終了またはキャンセルで停止します。

### Bluetooth フォールバック（オプトイン）

IP 経路がすべて使えないとき（AP 隔離、VPN/TUN による全トラフィック奪取、ルーター障害など）、ペアリング済みの端末同士は Bluetooth RFCOMM で**テキスト**の同期を継続できます。リンク上では bt1 セキュアチャネルが動きます — 既存のペアリング秘密鍵による HMAC-SHA-256 相互認証と、接続ごとに導出される AES-256-GCM 暗号化。システムの Bluetooth ペアリングは搬送路にすぎず、ClipSync 自身のペアリングと失効管理を代替することはありません。両端末ともデフォルトでは無効。IP が回復すると自動で切り戻します。画像は Bluetooth を通りません。

### インターフェース

- 初回オンボーディングはプラットフォームごとの内容で、スキップして設定から再表示できます。Windows は QR と特権読み取り / Bluetooth の選択肢を表示し、Android は読み取り経路と権限を説明してから各設定へ進みます。
- デイ/ナイトテーマ（システム追従または手動固定）、独自のデザインシステム（[デザイン憲章](docs/design/DESIGN-CHARTER.md)）。
- **19 の表示言語**（右から左に書くアラビア語を含む）。ソース言語は簡体字中国語です。

## ダウンロードとインストール

ビルド済みパッケージは [GitHub Releases](https://github.com/fraternidaddeng/clipsync/releases) から入手できます。

| ファイル | 用途 |
|---|---|
| `ClipSync-windows-x64.zip` | Windows ポータブル版（.NET ランタイム同梱、インストーラー不要） |
| `ClipSync-android.apk` | リリース署名済み Android APK |
| `*.sha256` | 各ファイルの SHA-256 チェックサム |

1. **チェックサムを検証**：`.sha256` ファイル（リリースノートにも記載）と照合します。Windows では `Get-FileHash`、Linux/macOS では `sha256sum -c`。
2. **Windows**（Windows 10 22H2 または 11、x64）：任意の場所に展開して `ClipSync.App.exe` を実行。バイナリは**コード署名されていない**ため、初回起動時に SmartScreen が警告することがあります — SHA-256 を確認のうえ「詳細情報 → 実行」を選んでください。初回起動時には通常ファイアウォールの警告が表示されます。「プライベートネットワーク」にチェックを入れて許可してください — 開ける必要があるのは受信 TCP `47654` だけです。警告が出ない、アカウントが管理者でない、以前に「キャンセル」を押した場合は、[docs/install.md](docs/install.md) 第 3 節に従って手動で規則を追加し、ネットワークの種類を確認してください。アンインストールはフォルダーとデータディレクトリの削除。「起動時に自動実行」やファイアウォールの許可を有効にしていた場合は、先にアプリ内でオフ / 削除してください（それぞれ現在のユーザーのスタートアップ項目と、システムのファイアウォール規則 1 つです）。
3. **Android**（Android 10 / API 29 以降、root 不要）：Releases の APK をインストールし、求められたら「不明なアプリのインストール」を許可します。デバッグビルドは署名が異なるため、リリース版の上には**インストールできません**。
4. Clash / Surge などのプロキシをグローバル / TUN モードで使っている場合は、インストールガイドに従って LAN 直結を許可してください。

ネットワーク設定、Tailscale、プロキシの注意点、Android 各段階の手順、トラブルシューティングを含む詳細なガイドは [docs/install.md](docs/install.md)（中国語。Windows ZIP にも同梱）にあります。

## クイックスタート

1. **端末をつなぐ**：2 台を同じ LAN に接続するか、両方に Tailscale を入れて Windows 側の 経路 → ネットワーク →「接続」カードの「追加リッスンアドレス」に `100.x.y.z` アドレスを登録します。
2. **ペアリング**：Windows → 経路 →「新しい端末とペアリング」で QR コードを表示。Android → 経路 → スキャン。両画面の証明書フィンガープリントを見比べて、双方で確認します。所要およそ 2 分。
3. **まずテキストを双方向で確認**：Windows からテスト文字列をコピーし、Android の別アプリから ClipSync へ共有します。自動適用されない場合は履歴からコピーし、経路の状態を確認してください。
4. **必要な場合だけバックグラウンド経路を選ぶ**：Android → 経路 → 本機読み取り → ガイドを開きます。特権直接読み取りは USB / ワイヤレスデバッグと Windows 側の端末検出が必要です。端末再起動後はホストをもう一度起動します。adb を使わないオーバーレイポーリングは電池と遅延が増えます。
5. **画像とバックグラウンドを確認**：両端の設定で画像同期を有効にして PNG/JPEG を試します。履歴への到着とクリップボードへの自動適用は別々に確認してください。Bluetooth フォールバックはテキストのみです。

## プライバシーとセキュリティ

- **ご利用前にお読みください**：[プライバシーとリスク](docs/privacy-and-risks.ja.md) — 内容はどこへ行くのか、誰が見られるのか、自分で気をつけるべきことは何か。
- コンテンツが流れるのは、あなたが明示的にペアリングしフィンガープリントを照合した端末間だけ。転送は TLS 1.3 + 証明書ピン留め（Bluetooth フォールバックは独自の認証付き暗号化チャネル）で保護されます。
- アカウントなし、クラウド保存なし、中継サーバーなし、テレメトリーなし、クラッシュレポート送信なし。
- クリップボードの本文がログや通知に入ることはありません — 専用テストで固定済み。診断エクスポートは安心して共有できます。
- Android のクラウドバックアップと端末間移行からは全面的に除外されています（クリップボード履歴は機微な平文データのため）。
- 削除はローカル優先：一方で削除しても、すでに相手へ届いたコンテンツをリモートで回収することはありません（Windows→Android 方向には同期済み項目のトゥームストーン伝播があります）。
- 詳細：[脅威モデル](docs/threat-model.md) · [プロダクトスコープと非目標](docs/product-scope.md) · プロトコル [v1](docs/protocol-v1.md)、[v2（画像）](docs/protocol-v2.md)、[bt1（Bluetooth）](docs/protocol-bt1.md)。

## 現在のステータス（正直な注記）

- [実機 QA の記録](docs/manual-qa-results.md)には Windows 11 + Redmi Note 11T Pro の複数回の結果と既知の制限があります。[端末マトリクス](docs/device-validation-matrix.md)は未完成のため、他の ROM の互換性を示すものではありません。
- 自動テストには各プラットフォームの単体テストとクロスクライアント統合テストが含まれます。各端末のバックグラウンド・画面オフ・電池の確認は別途必要です。
- **Windows バイナリは未署名**です — SmartScreen の警告が出ます。実行前に SHA-256 を確認してください。
- **Android は GitHub Releases のリリース署名済み APK からインストールしてください**。デバッグ APK は署名が異なり、上書きインストールできません。
- **特権直接読み取り**のチャネルは端末の再起動をまたいで生き残りません — PC から再起動してください（Windows ならワンクリック）。ワイヤレスデバッグでは、画面オフやネットワーク切り替え後に端末の `IP:ポート` が変わることがあります。現在の値で再接続すれば OK で、ペアリングのやり直しは不要です。
- 設計上やらないこと：iOS/macOS/Linux クライアント、ファイル転送（LocalSend をどうぞ）、アカウント、クラウド中継、NAT 越え、テレメトリー。詳しくは[プロダクトスコープ](docs/product-scope.md)。

## ソースからビルド

前提条件：Git、.NET 8 SDK（`global.json` で固定）、JDK 17、Android SDK Platform 35、PowerShell 7 推奨。

```powershell
pwsh ./scripts/build-windows.ps1       # Windows アプリのビルド + テスト
pwsh ./scripts/build-android.ps1       # Android アプリのビルド + テスト
pwsh ./scripts/validate-protocol.ps1   # 共有プロトコル fixtures の検証

pwsh ./scripts/package-windows.ps1     # dist/ClipSync-windows-x64.zip (+ .sha256)
pwsh ./scripts/package-android.ps1     # dist/ClipSync-android.apk    (+ .sha256)
```

リリース APK の署名は環境変数 `CLIPSYNC_ANDROID_*` からのみ読み込みます（キーストアはリポジトリに決して入りません）。パッケージング・署名・タグ駆動のリリースワークフローは [docs/install.md §10](docs/install.md) を参照してください。

リポジトリ構成：

- `docs/` — プロダクト、セキュリティ、プロトコル、Android 機能、ADR、検証の記録
- `protocol/` — JSON Schema と言語横断の共有 fixtures（`v1/`、`v2/`、`bt1/`）
- `windows/` — .NET 8 WPF アプリと xUnit テスト
- `android/` — Kotlin/Compose アプリと JVM ユニットテスト
- `scripts/` — 再現可能なビルド・検証・パッケージング・明示的な adb 検査コマンド

ブランチ運用：`main` は常にリリース可能。テストと受け入れチェックに合格した作業だけが `main` に入ります。
