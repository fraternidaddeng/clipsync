# 发布前人工 QA 清单（Windows + Android）

- 日期：2026-08-24
- 分支：`cursor/implement-charter-ui-1991`
- 适用场景：每次发布候选构建（RC）在真实设备上的全量人工验收。自动化测试已证明的部分见 `docs/verification-without-device.md`，本清单只列**机器证不了、必须人过**的项。
- Android 后台读取档位的验收不在本页展开，按 `docs/device-validation-matrix.md` 的 S0–S4 脚本化步骤执行。
- 记录纪律：每项打勾须附操作者、日期、构建 commit；任何失败项记录复现步骤与截图（截图不得含真实剪贴板敏感内容）。

## 0. 环境与构建准备

- [ ] Windows 侧构建自 `scripts/build-windows.ps1`，Android APK 构建自 `scripts/build-android.ps1`，两端 commit 一致并记录。
- [ ] CI 三个作业（validate-protocol / build-windows / build-android）在该 commit 上全绿。
- [ ] 测试网络：两台设备同一 Wi-Fi，无 AP 隔离；另准备一个次要 Wi-Fi 或热点用于切网测试。
- [ ] Windows 防火墙对 47654 端口的放行提示已按预期出现并允许。

## 1. 安装与首次运行

### Windows

- [ ] 全新机器（或清空数据）首次启动：主窗口、托盘图标正常出现，无崩溃、无缺字体（随包 Noto Sans SC / Plus Jakarta Sans / JetBrains Mono 生效，不回退系统字体）。
- [ ] 日/夜主题跟随系统切换实时生效，三个窗口（主窗、配对、诊断）无残留旧配色。
- [ ] 自绘标题栏可拖动、最小化/关闭行为正确；关闭到托盘不退出进程。

### Android

- [ ] 全新安装首次启动：首次运行引导完整播放，能力上限文案如实（不承诺后台读取默认可用）。
- [ ] `POST_NOTIFICATIONS` 引导出现；拒绝后应用内出现「通知已关闭」状态行，不反复骚扰。
- [ ] 三个 tab（一屏 / 通路 / 偏好）均可进入，空状态文案正确显示。

## 2. 配对（pairing）

- [ ] Windows「配对新设备」生成 QR 弹窗，二维码在手机摄像头 30 cm 距离内可稳定识别。
- [ ] Android 扫码后两端各自显示证书指纹，**逐组核对一致**后双向确认，配对完成。
- [ ] 配对后 Windows 设备列表出现手机（名称正确），Android「偏好 → 管理配对」显示电脑名称。
- [ ] 一次性配对令牌不可复用：用旧二维码重扫应失败并有明确报错。
- [ ] 撤销：Windows 侧「撤销所选设备」后活跃连接立即断开，手机端如实显示未配对；重新配对视为新设备（旧密钥作废）。
- [ ] 反向撤销（Android 侧解除配对）同样立即生效。
- [ ] UDP 发现广播在真实路由器上可达（广播内容只含设备 ID/端口/指纹，抓包抽查不得含正文）。

## 3. 双向同步（sync）

- [ ] Windows 复制文本 → 手机「一屏」出现该条目；手机前台复制 → Windows 历史出现该条目（含来源徽标）。
- [ ] 手机入站默认自动写入系统剪贴板；关闭 `auto_apply_remote` 后只进历史/收件箱，绝不写剪贴板。
- [ ] 回环抑制：自动写回的内容不得再次上行（两端各验一次）。
- [ ] 相同文本的真实二次复制仍然上行（不被回环抑制误杀）。
- [ ] 断线补齐：一端断网期间复制 3 条 → 恢复后按序补齐、不重不漏；两个方向各测一次。
- [ ] 100 次循环互拷：无重复、无串位、无回环（可配合矩阵 S1 步骤 4 合并执行）。
- [ ] 延迟验收：同 Wi-Fi 下复制 → 对端可粘贴 P95 ≤ 2 s（样本 ≥ 50 次）。
- [ ] 超限内容（> 1 MiB）：本机保留、明确提示不同步，无静默截断。
- [ ] Wi-Fi 切换 / 弱网 / Windows 睡眠唤醒后自动重连，恢复后无需人工干预即可继续同步（记录恢复耗时）。

## 4. 暂停与私密（pause / private）

- [ ] Windows「暂停捕获」：开启后本机复制不再入库，历史保留；恢复后新复制正常。
- [ ] Windows「私密模式」：开启期间复制不留痕迹；来源进程黑名单（如密码管理器）进程的复制被拦截。
- [ ] Android 暂停/私密：前台捕获、分享面板、磁贴、通知复制全部不上行；恢复后此前被暂停的队列按设置补投、无丢失。
- [ ] 一端暂停不影响另一端接收其余设备内容。
- [ ] 托盘/通知的暂停状态图标与实际状态一致（见第 5、6 节）。

## 5. Windows 托盘（tray）

- [ ] 托盘四态图标（正常流动 / 暂停 / 私密 / 需注意）随状态实时切换，无错态。
- [ ] 托盘浮窗（440px）：最近剪贴列表正确、点击条目行为正确、暂停开关即点即生效并与主窗同步。
- [ ] 托盘菜单可打开主窗口、诊断查看器、退出；退出真正结束进程与监听端口。
- [ ] 诊断查看器：会话日志滚动正常，抽查**不含**剪贴板正文、密钥、nonce。

## 6. 通知（notifications）

### Windows

- [ ] 认证节流锁定时出现锁定通知，文案可理解、不含敏感值。
- [ ] 捕获降级（剪贴板被抢占 / `CaptureFaulted`）横幅在真实抢占场景下触发并可恢复。

### Android

- [ ] `connectedDevice` 前台服务通知常驻且文案如实反映连接状态；FGS 被系统拒绝时按降级路径提示而非假装在跑。
- [ ] 入站通知「复制」动作在锁屏 / 横幅 / 免打扰三种状态下行为符合系统预期，点击复制成功。
- [ ] 自动写入状态通知与开机「需要恢复」通知（开机恢复开启时）真实出现。
- [ ] 通知渠道命名与分组合理，可单独关闭某一类而不影响其余。

## 7. 历史与数据管理

- [ ] 双端历史搜索、单条删除、清空全部生效；删除以 tombstone 传播到对端、不带正文。
- [ ] 保留期限设置生效：超期条目在两端被清理。
- [ ] 手机端收件箱在自动写入关闭时可手动取用每一条。

## 8. 导出（export）——依赖并行任务落地

> 历史导出/导入功能由并行任务从 `feature/stage-4` 移植，截至 2026-08-24 尚未合入本分支。功能落地前本节整体记 `N/A`；落地后按下列步骤执行。

- [ ] 导出产物不含密钥/配对 secret；文件权限与存放路径提示合理。
- [ ] 导出 → 清空 → 导入往返后历史条目数与内容一致（抽查 10 条）。
- [ ] 跨设备导入（换机场景）：新装实例导入旧导出文件后历史可读、可搜索。
- [ ] 导入损坏/篡改文件时明确报错，不产生半截数据。

## 9. 发布收尾

- [ ] 版本号、`CHANGELOG.md` 与发布说明（`docs/release-notes-template.md`）已更新且与实际构建一致。
- [ ] 发布产物 SHA-256 校验值已生成并写入发布说明。
- [ ] `docs/device-validation-matrix.md` 中本次 RC 实测过的槽位状态已更新（未测的保持 `NOT_TESTED`，不得顺手改绿）。
- [ ] 已知缺陷清单（本清单中失败/跳过项）已汇总进发布说明「已知限制」。

## 通过标准

第 0–7、9 节全部通过（第 8 节视功能是否落地）即可出 RC；任何配对、安全边界（指纹核对、撤销、日志卫生）或数据一致性（补齐、去重）项失败为**发布阻断**，延迟类项失败降级为已知限制并须写入发布说明。
