# ClipSync 产品范围

状态：阶段 0 冻结基线  
适用平台：Windows 10 22H2 及以上、Android 10（API 29）及以上

## 目标

ClipSync 是供个人、小范围设备使用的纯文本剪贴板同步工具。它不依赖账号、云数据库或公共 Relay；Windows 作为直连监听 peer，Android 主动连接。设备必须通过局域网、VPN 或用户配置的端口转发彼此可达。

第一版的核心价值是：内容先在产生端持久化，再在已配对设备之间近实时交换；短暂断线后能够补齐缺失事件，且不重复、不回环。

## 第一版必须提供的能力

- Windows 在后台捕获普通 `Ctrl+C` 产生的纯文本，写入本地历史并发送给已配对 Android。
- Android 收到远端文本后先写入收件箱；公开写入可用时优先自动应用，失败后才使用用户已授权的 Shizuku/overlay 回退，否则提供通知或历史条目供手动复制。
- Android 通过分享面板、快捷磁贴或前台模式发送文本；完成能力引导且所选读取 backend 健康时，也可后台捕获并自动上行。
- 两端采用对等事件 ID 与来源序号，先落库、后入 outbox；重连通过连续游标和缺失范围恢复。
- 提供可搜索历史、本地删除、过期、暂停同步、私密模式、设备撤销和敏感来源排除。
- 默认仅同步纯文本；单条同步上限为 1 MiB，超限不得静默截断。

## Android 能力承诺

后台读取与写回是两项独立能力，网络在线也不代表剪贴板可读或可写。读取模式按以下顺序探测：

1. `SHIZUKU_EVENT`
2. `ADB_LOG_OVERLAY`
3. `OVERLAY_POLLING`
4. `FOREGROUND_ONLY`

没有特殊权限时，分享、磁贴、前台读取和通知复制仍必须可用。任何特殊能力都要求用户可见的用途说明、状态和撤销路径；权限存在或代码可编译不能单独作为 `READY` 的依据。

## 数据、信任与网络边界

- 只在明确配对并相互确认指纹的设备之间传输内容。
- TLS 1.3 与证书指纹固定保护直连传输；pair secret 分别由 Windows DPAPI 和 Android Keystore 保护。
- Windows endpoint 是 peer 的通信角色，不是账号后端，不保存全局用户状态。
- 没有 LAN、VPN 或端口转发提供网络可达性时不承诺同步。
- 第一版删除是本地删除，不远程撤回已经到达其他设备的内容。
- 普通日志只允许状态、稳定错误码和计数，禁止剪贴板正文。

## 明确不做

- iOS、macOS、Linux 客户端或 Windows 之间的全网状同步。
- 账号、登录、订阅、团队空间、多租户、云数据库、公共 Relay 或公网 NAT 穿透。
- 公共分享链接、社交、评论、协作编辑。
- AI 摘要、翻译、OCR、自动分类或推荐。
- 通用文件传输、文件夹同步、媒体图库；文件传输继续使用 LocalSend。
- 远程桌面、键鼠、通知或短信同步。
- Root、降低 Android `targetSdk`、静默 adb、隐藏授权、完整输入法或无障碍监听。
- 默认遥测、剪贴板内容日志或云端崩溃上报。
- 对任何第三方私有协议、品牌或界面的兼容与复制。

## 范围变更规则

新增功能必须明确服务于捕获、传输、恢复、检索或信任/隐私之一，并记录决策。协议字段、数据库结构和配对行为发布后只允许通过版本化迁移修改。阶段验收失败时不得进入下一阶段。
