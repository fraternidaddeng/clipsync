## 本版亮点

**这一版把 Android 的「特权直读」真正修通了——在此之前，这条通道从未成功读到过一次后台剪贴板。**
症状是通路页两项前提全绿（宿主 ping 得通、已授权），读取却恒报 `PRIV_HOST_USERSERVICE_DEAD`，
系统只能降级用悬浮窗轮询。病根在 `AndroidManifest.xml`：为 shizuku authority 注册的 provider 类
    40|一直是官方基类 `rikka.shizuku.ShizukuProvider`，而只有 ClipSync 自己的子类才处理 UserService 子
进程交回剪贴板 binder 所用的 `sendUserService` —— 子类从未被注册，于是 binder 回传永远落空。此前
多轮针对该错误码的修复都是在改 UI 诚实性与自愈重试，治标未及病根。

同时修掉一处让**无线调试**下「一键启动特权直读」必然失败的合谋：启动脚本清理旧宿主时逐 pid 遍历
`/proc`，在真机（861 个进程）上仅此循环就要 26.7 秒、整脚本无线下 30.6 秒，而电脑端对每条 adb 命令
一律 30 秒硬超时——adb 被杀在遍历中途，`app_process` 从未执行；USB 以约 5 秒余量侥幸通过，于是表现
为「USB 行、无线不行」。现改为一趟 `pgrep`（0.2 秒级），并为启动脚本单独放宽超时预算。

**谁该升级：所有使用或想使用 Android 特权直读（后台/息屏即时捕获）的用户。** 其余用户升级可获得
本版一并归入的图片同步默认开启、Android「后台同步服务」总开关、Windows 暂停同步全局快捷键，以及
    50|一批同步链路（删除传播、墓碑竞态、图片去重、私密模式写入）的缺陷修复。

## 变更明细

逐条流水见 `CHANGELOG.md` 的 `[0.2.0]` 节（含根因、真机实测数据与测试账目）。以下为归并摘要。

### 新增

- [Android] 偏好 · 同步新增「后台同步服务」总开关（`sync.service_enabled`）：关即真关——前台服务停止、
  后台读取后端停转、常驻通知消失，重开应用与重启手机都不自行恢复。
- [Android] 偏好 · 捕获新增「暂停自动捕获」常驻开关（`sync.capture_paused`），与常驻通知动作同键互通。
    60|- [Windows] 暂停同步全局快捷键（`hotkey_pause`，默认关），与托盘浮窗暂停按钮同一意图。

### 变更

- [双端] **图片同步默认开启**，且**远端图片自动写入剪贴板亦默认开启**（2026-08-28 产品裁决；ADR 0004
  增补修订记录）。只改产品默认，不动任何拦截与安全语义：暂停/私密仍双杀自动写入，MIME 魔数、尺寸与
  哈希校验、v1 会话拒图、未接线宿主的 fail-closed 闸一律保留；用户显式关过的持久化值仍被尊重。

### 修复

- [Android] **特权直读病根：manifest 注册了官方 `ShizukuProvider` 而非 `ClipSyncShizukuProvider`**，
    70|  导致 UserService binder 经 `sendUserService` 回传永远落空、读取恒报 `PRIV_HOST_USERSERVICE_DEAD`
  （USB 与无线同时命中）。新增 Robolectric 回归例钉死 authority → 子类的绑定。
- [双端] **无线调试下「一键启动特权直读」必然超时**：启动脚本的逐 pid `/proc` 遍历改一趟 `pgrep`；
  Windows 侧 `IAdbRunner` 支持按命令超时，启动脚本单给 120 秒预算，其余命令维持 30 秒快超时；
  超时被杀时不再丢弃已捕获输出（已打出 `spawned` 的场景照旧进入 pgrep 复核）。
- [Android] 特权直读验证读补齐「宿主活着但读取服务已死」的应用侧自愈；「测试后台读取」不再抢跑冷启动
  的 UserService 绑定（约 12 秒有界等待）；通路页不再以持久化的「已实测」盖过活体死亡。
- [双端] 同步链路多轮深查修复：Windows 私密模式不再自动写入远端剪贴；Android 入站 `deleted` 墓碑对
  已收活体生效（Windows→Android 删除传播）；墓碑 outbox 确认竞态；图片去重不再信任公告头元数据；
  重复 `clip_payload_begin` 不再静默顶替在途传输；Windows 会话结束清扫半收图片临时文件。
    80|- [Android] 悬浮窗轮询不再让第三方全屏视频的虚拟导航键反复闪现（逐栏镜像系统栏申明）。
- [Android] 回声抑制表的跨线程数据竞争；`clipboard-share` 目录无限增长。
- [双端] 图片同步开关翻动立即对活动会话生效（含拨号窗口竞态）；Windows 应用 JPEG 的回环回声；
  Android 真实应用剪贴板形状读取（`image/` 通配、`image/jpg`、`text/uri-list`、条目多于 mime 不崩溃）。

### 安全

- 全库密钥泄露审计（2026-08-27）：全历史 375 提交逐 blob 扫描私钥块与多家云/服务凭据形态、全历史

## 已知限制

   110|- **特权直读的端到端验证只覆盖一台机型**（device `xaga` / MIUI / Android 13）。该通道依赖
  `app_process`、hidden API 与 ROM 对 adb shell 的具体行为，其余 ROM 未实测；矩阵回填前不作承诺。
- 特权直读通道**不会自愈跨重启**：手机重启或宿主被系统回收后，需从电脑重跑一次启动命令
  （Windows 端一键）。无线调试的 `IP:端口` 在息屏/切网后会漂移，需按手机无线调试页当前值重连。
- Android 后台**图片**捕获仍只走前台通道：三条后台读取路线与分享面板均为文本，复制图片需 ClipSync
  在前台（既有设计边界）。
- 蓝牙备援仅文本，蓝牙窗口内的图片事件标记「仅本机保留」，恢复 IP 后**不会**补传（ADR 0005 §4）。
- Windows 二进制**未代码签名**（SmartScreen 会告警，请先核对 SHA-256）；超大截图（约 800 万像素以上
  的 32bpp DIB）受 `DibCodec` 32 MiB 分配守卫所限会静默不捕获（已知权衡）。
- Windows 剪贴板生态共存（密码管理器、RDP、Office 抢占）与防火墙/多网卡场景未系统实测。
   120|- 平台边界（设计取舍，非缺陷）：不做 iOS/macOS/Linux、不做文件传输（用 LocalSend）、不做云中转/
  NAT 穿透（不可达网络就是不同步）、不做账号/遥测。
