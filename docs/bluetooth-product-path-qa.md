# 蓝牙备援产品路径人工 QA（给本机 agent 的执行清单）

- 适用分支：`main`。执行前 `git pull`，双端从**同一 commit** 构建并记录（Windows `scripts/build-windows.ps1`，Android `scripts/build-android.ps1`）。
- 背景：阶段 0 spike 已 GO（`docs/bluetooth-phase0-report.md`），但那走的是 spike 工具路径。本清单测的是**产品内路径**：Windows `BluetoothSyncHost`/`RfcommServer` × Android `BluetoothSyncConnector`/`SyncSupervisor`，即用户真实会用到的开关、拨号、回切。
- **本清单与其执行结果均不构成 READY 声明。** 这只是阶段 5 矩阵（AP 隔离、Doze 过夜、多适配器/多 OEM 等，见 `docs/bluetooth-fallback-plan.md` 阶段 5）之前的最小产品路径闭环。全部通过也只说明「这一对设备上产品路径能跑通」。
- 记录纪律：每项附操作者、日期、构建 commit、原始观察（状态文案照抄）；截图/日志**不得含真实剪贴板正文**。结果按 `docs/manual-qa-results.md` 的样式新增一节带日期的记录；`docs/device-validation-matrix.md` 的槽位不因本清单改动。

## 0. 前置条件

- [ ] 两台设备已完成剪剪相传扫码配对（`docs/install.md` 第 6 节），IP 路径此刻能正常同步（先复制一条文本验证双向可达，再开始测蓝牙）。
- [ ] 两台设备已在**系统设置里完成蓝牙配对（bonded）**。小米等 OEM 上 Windows「添加设备」常扫不到手机：改从手机系统蓝牙「可用设备」列表点电脑名发起（`docs/install.md` 第 7 节步骤 1）。
- [ ] 双端系统蓝牙开关为开；Android 前台服务（同步通知）在跑。

## 1. 开启双端开关

入口以实际构建为准：当前 `main` 上双端开关都在**偏好**页；settings-roadmap §四的 IA 迁移会把它挪到**通路 · 网络段**，若你手上的构建已合入迁移，就去通路页找，行为判据不变。

- [ ] **Windows**：剪剪相传 → 偏好 → 「同 步 · SYNC」组 → 打开「蓝牙备援」（默认关）。无需重启：通路页「网络」段的蓝牙状态行应变为「**蓝牙备援待命 · LAN 不可达时手机自动改走蓝牙**」。诊断日志出现 `bluetooth_fallback_started`。
- [ ] Windows 负例：若适配器缺失/无线电关闭，状态行应如实显示「**蓝牙备援不可用：蓝牙适配器不可用或已关闭**」（日志 `bluetooth_start_failed_*`），开关关-开一次即重试。不得显示「待命」假装可用。
- [ ] **Android**：剪剪相传 → 偏好 → 「蓝牙备援」组 → 打开开关（默认关）。API 31+ 首次开启应弹「附近的设备」（`BLUETOOTH_CONNECT`）运行时权限请求。
- [ ] Android 负例：拒绝权限后开关保持诚实——备援不参与拨号，其余通路不受影响；下次拨号周期重查权限，无需重启服务。

## 2. 选择 bonded 目标设备

- [ ] Android 开关打开后出现「蓝牙目标设备」行（未选择时提示先在系统设置里完成蓝牙配对）。点击 → 内联列出系统 bonded 设备 → 选中你的电脑，行内显示「当前：<电脑名>」。
- [ ] 负例：系统蓝牙关闭或无 bonded 设备时，列表如实说明原因（不装作功能坏了）。
- [ ] 未选设备时备援不拨号（开关开着也一样）——这是三前提之一：开关 + 权限 + 选定设备。

## 3. 制造 IP 不可达（断 LAN / 强制代理）

先确认要测的是「IP 全失败 → 蓝牙兜底」，任选其一，保持**手机蓝牙开着**：

- 方式 A（强制代理）：手机 Clash/VPN 开 TUN/全局接管并**去掉局域网直连/绕过规则**（与 `docs/install.md` 第 5 节的放行配置相反），使电脑的 LAN IP 不可达。
- 方式 B（切断 LAN）：直接关手机 Wi-Fi，或把手机切到与电脑不通的另一网络/热点。

- [ ] 先看到 IP 路径确实死了：Android 通知转为「连接断开 · 等待重连」。若跳过这步，后面测到的可能仍是 IP 会话。
- [ ] 等待蓝牙拨号：每个重连周期先拨全部 IP 候选、全失败后追加**一次**蓝牙拨号，退避上限 60 秒——最多等约 2 分钟。切网动作本身会触发立即重试（nudge）。

## 4. 验证蓝牙文本同步

- [ ] Android 通知变为「**已连接 · 蓝牙备援（仅文本）**」；通路页网络段显示「**已连接 · 蓝牙备援**」及说明（IP 不可达、仅文本、IP 恢复自动切回）。
- [ ] Windows 通路页蓝牙状态行变为「**蓝牙备援 · 正与 <设备名> 同步（仅文本）**」。
- [ ] Windows 复制文本（用一次性合成标记，如 `QA-BT-<commit短SHA>-w2a-1`）→ 手机「一屏」出现该条。
- [ ] 手机复制/分享文本（`QA-BT-…-a2w-1`）→ Windows 历史出现该条，来源徽标正确。
- [ ] 蓝牙窗口内的补齐：蓝牙会话中一端连续复制 3 条 → 对端按序收到、不重不漏（速度慢于 LAN 属预期，实测吞吐参考约 150–180 KiB/s）。
- [ ] 记录建连与传输的大致耗时；无内容的敏感值（密钥、nonce、正文）不得出现在诊断日志/logcat 中（抽查）。

## 5. IP 恢复回切

- [ ] 恢复 LAN（关代理接管 / 重开 Wi-Fi）。蓝牙会话期间每 30 秒探测一次 IP，网络可用信号会立即触发探测：预期**约 30 秒内**（有 nudge 时更快）切回 IP。
- [ ] 切回后：Android 通知回到「已连接 · 剪贴同步在线」；Windows 蓝牙状态行回到「蓝牙备援待命 …」；蓝牙会话已优雅关闭（任一时刻只有一条活动会话）。
- [ ] 回切后再复制一条文本，确认走 IP 正常同步；蓝牙窗口内产生的**文本**在此前已到齐，无重复。

## 6. 图片：仅本机保留

蓝牙会话强制协议 v1，图片事件在线上只作为 `local_only` 终止标记推进游标（ADR 0005 §4），**事后 IP 恢复也不补传**。

- [ ] 蓝牙会话期间在一端复制一张图片（「同步剪贴板图片」开关开与关都一样——蓝牙上图片一律不传）：图片正常进入**本端**历史；**对端不出现**该图片，也无报错。
- [ ] 图片之后再复制一条文本：文本照常到达对端（`local_only` 标记已让游标越过图片，不阻塞后续同步）。
- [ ] IP 恢复后：该图片**仍不出现**在对端（不补传）；需要时手动重新复制才会同步。
- [ ] 诚实记录 UI 现状：ADR 0005 §5 要求历史中给这类图片标注「仅本机保留」，当前 `main` 双端 UI **尚未实现该标注**（应用内文案与 `docs/install.md` 已说明此行为）。标注缺失记为已知缺口，不算同步行为失败；若你的构建已出现标注，照实记录其文案。

## 7. 加测（可选，各一条即可）

- [ ] 暂停/私密门与 IP 路径共用：蓝牙会话中开启暂停或私密，出站立即停；恢复后继续。
- [ ] 撤销压倒承载层：一端撤销配对后，蓝牙握手必败（系统 bonded 关系还在也一样），不得建立会话。

## 8. 结果归档

- 在 `docs/manual-qa-results.md` 新增带日期的一节（或新建当日记录），逐项填 通过 / 失败 / 未测 + 原始观察；失败项附复现步骤。
- 不改 `docs/device-validation-matrix.md` 槽位；蓝牙产品路径的矩阵化验证（多适配器/OEM、AP 隔离、Doze 过夜等）仍属阶段 5，不因本清单通过而视为完成。
- **任何文档、UI、发布说明都不得因本清单的结果出现 READY 字样。**
