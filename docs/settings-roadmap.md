## 一、判据（先立规矩）

一条设置住在哪，用一句话判定：

> **它改变「内容能不能到达对端」吗？改变 → 通路。只改变「我用起来舒不舒服 / 本机留存什么 / 应用怎么跑」→ 偏好。**

- **通路** = 连通性与剪贴板读取路径：四段管道、读取路线引导、权限、配对、设备管理、网络与蓝牙备援。它是**诊断仪表**，回答「通不通、堵在哪」。
- **偏好** = 使用舒适度与应用行为：显示、捕获取舍、历史留存、通知、启动方式、数据进出。

推论（本文提案的两个 IA 迁移由此而来）：**蓝牙备援**与**额外监听地址**改变的是「能不能到达」，曾住在偏好——应迁回通路网络段。**（已完成：2026-08-25 连同本机证书指纹一并迁入通路网络段，偏好侧各留一个发布版本的链接行指路，见 P1 #10–12。）**

### 2.3 通路已有的（两端）

### 2.4 两端已是「跟随系统、无设置」的

- **主题**：Windows 读 `SystemUsesLightTheme` 并监听切换；Android 用 `isSystemInDarkTheme`。均无手动覆盖。
- **字体缩放**：Android 用 sp，随系统字体大小；Windows 全部硬编码 px，不随任何缩放（DPI 除外）。
- **时间显示**：今天 `HH:mm`、昨天、更早按日期——混合格式是已裁决的设计，不设开关。

## 四、信息架构提案

### 4.1 目标结构

```
剪剪相传
├─ 一屏（历史）
│
├─ 通路 ────────── 连通与读取路径：「通不通、堵在哪」
│   ├─ 本机读取/捕获段   读取路线引导、权限（UI 永不出现 Shizuku 字样，只说「特权直读」）
│   ├─ 本机服务段        前台服务启停
│   ├─ 网络段            配对 · 设备管理（撤销、设备色）
│   │                    ← 迁入：蓝牙备援 + 目标设备（双端）
│   │                    ← 迁入：额外监听地址（Windows）
│   │                    ← 迁入：本机证书指纹（Windows，配对时核对用）
│   └─ 对端写入段 /（Android）本机写回段
│
└─ 偏好 ────────── 使用舒适度与应用行为
    ├─ 显示    历史字号 · 预览行数 · 外观（跟随系统/日间/夜间）
    ├─ 同步    暂停同步 · 私密模式 · 自动写入（文/图） · 图片同步
    ├─ 捕获    屏蔽进程（Win） · 跳过敏感内容（Android）
    ├─ 历史    自动过期清理 · 保留时长（两端都可调） · 保留条数 · 单条上限（只读）
    ├─ 运行    开机自启+静默启动（Win） · 开机恢复（Android） · 收到内容通知（Android） · 呼出浮窗快捷键（Win）
    ├─ 数据    导出历史 · 导入历史 · 清空历史
    └─ 设备    已配对设备 → 通路（链接行，保留）
```

### 4.2 结构决策

- **Android 不拆子页面**。现在约 12 行、提案后约 18 行，单页滚动 + mono 组头仍然成立；拆二级页面反而破坏「一屏一个主角」的密度控制。分组从 5 组调成 7 组（显示、同步、捕获、历史、运行、数据、设备）。
- **Windows 沿用偏好页分组卡**，新增「显示」「运行」两张 GroupCard；「信任」卡随指纹迁往通路后取消。
- **开机恢复（Android）留在偏好**：它决定「应用要不要自己爬起来」，是应用行为；服务当下通不通由通路本机服务段陈述。两者是「意愿」与「事实」的分工。
- **迁移不新增能力**，只是把三条连通性配置搬回它们语义上的家（判据见 §一）。迁移时偏好页保留一个发布版本的链接行指路（「已移至通路 · 网络」），下个版本删。

### 4.3 命名规约（按纲领）

- UI 永不出现 Shizuku、READ_LOGS、binder、EXTRA_IS_SENSITIVE 等实现名词；说「特权直读」「日志感知」「标记为敏感的内容」。
- 「不可用」陈述事实不扮演错误；用户关掉的东西（通知、自启）是选择，用灰面事实条，不用红。
- 长说明是隐私承诺（纲领 5.9），新增设置的描述文案照此标准写足。

| 应用锁（生物识别 / PIN） | 历史是本机数据库，设备锁屏已是边界；应用内再加一道锁是新的信任面，v1 不开 |
| 云备份 / 定时自动备份 | product-scope 明确无云；手动导出/导入已覆盖数据迁移 |
| 自定义主题色 / 主题编辑器 | 设计纲领是权威配色记录，色相配额与彩度三档不是用户变量 |
| 单条上限调节 UI | 1 MiB 是协议承诺；存储虽支持调低，但没有真实场景，UI 保持只读事实行 |
| 通知显示正文开关 | 通知**永不**含剪贴板正文是隐私承诺（plan.md），承诺不做成开关 |
| Windows 关闭行为选项（关闭=退出 vs 收托盘） | 关闭收托盘 + 托盘菜单「退出」是唯一动线；加开关只制造歧义 |
| 时间格式切换（相对/绝对） | 今天 `HH:mm`、昨天、更早按日期的混合格式已是裁决过的设计 |
| 历史项点按行为自定义、声音/振动反馈、历史合并展示开关 | 无诉求先不做；合并展示（plan.md hash dedup）等图片/去重工作面成熟后再议 |

## 六、实施顺序建议

1. **P0-2（Android 保留时长）** 最小改动先行，消除双端不对称。
2. **P0-3（Windows 自启）+ P0-4（Android 敏感标记）** 互不相干，可并行；后者补上范围承诺。
3. **P0-1（历史字号）** 两端各自动类型阶管线，先 Android（sp 系数）后 Windows（FontSize 收敛为 DynamicResource）。
4. **P0-5（清空历史）** 与导出导入同屏，做完数据组闭环。
5. P1 里 **IA 迁移（10–12）宜打包成一轮**「通路收编连通性配置」的独立改动，避免与功能新增混在一个 diff。

新增存储键命名规约：Android 沿用 `clipsync.settings` 一个文件，UI 类键用 `ui.` 前缀、捕获类用 `capture.`、通知类用 `notify.`（现有 `sync.` 键一律不动）；Windows settings 表用对应蛇形键。任何键一经发布只增不改，与协议字段同规。
