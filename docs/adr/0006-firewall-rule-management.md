# ADR 0006：Windows 防火墙规则的检测与管理

- 状态：已接受（2026-09-03 用户拍板；Windows 端同日落地——`ClipSync.App/Firewall/` 的只读检测 `FirewallInspector`、`FirewallRuleCommand`、经 UAC 运行 netsh 的 `FirewallRuleElevator` 与确认窗 `FirewallRuleWindow`，通路页网络段「防火墙」状态行 + 连接卡「放行 TCP 47654 入站」一行）
- 日期：2026-09-03
- 关联：`docs/field-test-report-v0.2.0.md` 问题 1（防火墙未放行导致配对静默失败）；`docs/threat-model.md`「防火墙按公用配置文件放行 TCP 47654」一行；`docs/install.md` §3；`docs/privacy-and-risks.zh-CN.md` §7。不改变 ADR 0001 的直连 P2P 模型：Windows 监听、Android 主动连接。

## 背景

2026-09-01 的真机测试（Windows 11 Pro 非管理员会话 + vivo Android，同一局域网）中，手机扫码后提示「请在电脑上批准」，电脑始终没有批准窗口，约 90 秒后手机报「配对失败」。根因是 Windows 防火墙没有 TCP 47654 的入站放行规则：手机的配对确认请求被静默丢弃，应用根本没收到请求。管理员 PowerShell 手动加规则后配对立即成功。

三点事实决定了这不是靠文档能收口的问题：

1. **防火墙弹窗不可靠。** 「Windows 安全中心警报」只在特定条件下出现——会话有管理员权限、程序首次监听、此前没有为该程序建过规则。非管理员会话、用户之前点过「取消」（Windows 会建一条 Block 规则并不再弹）、以及网络被归为「公用」而用户只勾了专用，都表现为「什么都没发生」。文档此前预设弹窗一定出现。
2. **应用此前不写任何系统级配置。** `StartupRegistration.cs` 的姿态是 per-user HKCU `Run`、no elevation、no HKLM；发布形态是便携 ZIP，没有安装器，也就没有安装期加规则的机会。防火墙规则住在系统策略里，任何写入都需要管理员权限，这是项目第一次碰系统级配置。
3. **文档要求过宽。** README 三语与 `install.md` 此前要求同时放行 UDP 47653。复核 `UdpDiscoveryBroadcaster`：Windows 端 UDP 47653 只发不收，Android 端没有任何监听，因此入站放行只需 TCP 47654。多要一条规则既扩大暴露面又增加用户操作。

真机测试同时暴露：手机端「约 90 秒」与 Windows 端批准超时（`PairingService.ApprovalTimeout` = 90 s）吻合，说明也可能存在「请求已到达、批准窗口没被看到」的情形。批准窗口的任务栏闪烁与托盘气泡、诊断日志记录配对请求到达/超时/拒绝/成功，属配套修复，不在本 ADR 范围。

## 决策

### 1. 只读的防火墙状态检测（不需管理员）

- 通过 Windows 防火墙 COM 接口 `HNetCfg.FwPolicy2` 读取当前规则集与各配置文件（域/专用/公用）的启用状态，普通用户权限即可。
- 输出三态，并在通路页网络段如实陈述：
  - **已放行**：存在启用的入站 Allow 规则，协议 TCP、本地端口覆盖当前监听端口，且规则的配置文件范围覆盖当前活动网络类型。
  - **未发现放行规则**：没有这样的规则，或规则存在但被禁用 / 配置文件不匹配（如只放专用、当前网络为公用）——原因随状态一起显示。
  - **无法判断**：防火墙由第三方产品或组策略接管、COM 接口不可用、或查询抛错。此态不伪装成前两态。
- 状态行明说「**规则存在 ≠ 一定可达**」：第三方防火墙、路由器 AP 隔离、VPN/TUN 接管都在本检测的视野之外；可达性最终以手机能否连上为准。
- 检测同时列出针对 `ClipSync.App.exe` 的 Block 规则（用户此前点「取消」的产物），并提示其影响。

### 2. 一键放行：先展示命令，再以 UAC 执行

- 用户点「放行」后，应用**先原样展示将执行的命令**与配置文件范围，用户确认后才执行：

  ```text
  netsh advfirewall firewall add rule name="ClipSync TCP 47654" dir=in action=allow protocol=TCP localport=47654 profile=private
  ```

- 配置文件范围**默认仅专用网络**；界面提供「同时放行公用网络」复选框，勾选时 `profile=private,public`，并就地说明后果（公共 Wi-Fi 上同网段设备可触达该端口，读内容仍需配对）。
- 执行方式：以 `runas` 动词启动 `netsh.exe`，触发系统 UAC 对话框。用户在 UAC 上拒绝时，应用如实回显「未获得管理员权限，规则未创建」，随后重新检测；不把拒绝写成成功，也不重试骚扰。
- 规则名固定为 `ClipSync TCP 47654`，与 `docs/install.md` §3 手动命令使用的名字一致，便于用户在系统里辨认与删除。
- 展示区旁提供「复制命令」，用户可自行在管理员终端执行，不经应用提权。

### 3. 配套「移除该规则」

- 与放行同一入口、同一 UAC 流程：

  ```text
  netsh advfirewall firewall delete rule name="ClipSync TCP 47654"
  ```

- 只删应用自己命名的规则；用户手动建的其他规则不碰，检测中如实列出但不代删。
- 卸载路径写进 `docs/install.md` §3 第 4 步：用过放行的，卸载前在应用内移除或手动删除。

### 4. 按端口放行，不按程序路径

- 规则匹配 TCP 端口而不是 `ClipSync.App.exe` 的路径：便携包会被用户移动目录，应用内更新会替换整个目录，按路径的规则在这两种情形下都失效且不易察觉。
- 代价与如实提示：默认端口 47654 被占用时程序退到随机端口，此时端口规则不覆盖新端口。检测把「当前监听端口 ≠ 规则端口」列为「未发现放行规则」的原因之一，并提示先释放 47654 或改用手动规则；应用不把旧规则的存在当作已放行。

### 5. 透明度折衷

- UAC 对话框显示的发布者是 Microsoft 签名的 `netsh.exe`，不是 ClipSync，且不显示参数。用户在 UAC 上看不到「谁在加什么规则」。缓解：应用内先展示完整命令（第 2 条）+ 提供复制命令自行运行。
- 自提权替代方案（应用自身以管理员重启并经 COM `INetFwRules.Add` 写规则）会让 UAC 显示 ClipSync 自己——但发布包未做代码签名，UAC 会出现「未知发布者」的黄色横幅，反而更可疑。暂不采用；待有代码签名再评估。

## 后果

- 这是项目**第一个写系统级配置的功能**。卸载不再是「删目录即可」：`install.md` 与 README 三语的卸载说明改为如实表述（开机自启项、防火墙规则两处按需清理），应用内的移除按钮是主路径，手动 `Remove-NetFirewallRule` / `netsh ... delete rule` 是备用路径。
- 公用网络放行的暴露面记入 `docs/threat-model.md`（「防火墙按公用配置文件放行 TCP 47654」一行 + 剩余风险一句）与 `docs/privacy-and-risks.zh-CN.md` §7。
- 文档层面同步：README 三语与 `install.md` 去掉「放行 UDP 47653」的要求，保留「UDP 47653 做局域网发现广播，只发不收，不含剪贴板内容」的说明；`install.md` §3 补手动放行、网络类型检查、Block 规则查删；排障表同步。
- 检测与放行都是 Windows 专有代码，隔离在 `ClipSync.App`（WPF 宿主）而不进 `ClipSync.Core` / `ClipSync.Peer`，保持后两者的跨平台可测试性。
- 新增的用户可见文案遵循纲领 §5.9 措辞规范：写应用做什么、何时做，不写自我辩解式否认句。
- `docs/manual-qa-checklist.md` 第 0 节改为「已确认 TCP 47654 入站放行（弹窗允许或手动规则），并记录网络类型」；第 1 节 Windows 小节补应用内检测/放行/移除的真机验收项。

## 被否决的方案

- **安装器（MSI/MSIX）在安装期加规则**：项目没有安装器，便携 ZIP「解压即用、自带运行时」是 README 与 `install.md` 写明的发布形态；为一条防火墙规则引入安装器不成比例。
- **应用自提权 + COM `INetFwRules.Add` 写规则**：技术上最干净、UAC 上显示 ClipSync 自己，但发布包未签名会触发「未知发布者」横幅。**暂缓**，有签名后重评。
- **应用启动时自动尝试加规则**：需要提权，等于每次启动弹 UAC；与「用户明确同意才碰系统配置」相悖。
- **按程序路径放行**：便携包移动与更新替换目录后规则失效（见决策 4）。
- **同时放行 UDP 47653**：复核代码后确认只发不收，入站放行无意义。
- **只写文档，不做应用内检测与放行**：真机测试证明文档已经写了、用户也没看到弹窗、还是卡住了。保留为回退路径（`install.md` §3 的手动命令），不作为唯一路径。
