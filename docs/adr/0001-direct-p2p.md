# ADR 0001：采用无账号的直接 P2P 模型

- 状态：接受
- 日期：2026-08-12

## 背景

产品只面向个人的小范围 Windows 与 Android 设备，需要复制即同步、断线恢复和设备信任，但不需要账号、云存储、多租户或公共分享。两端在普通网络环境中并不总能相互接受入站连接，Android 后台监听也更易受生命周期限制。

## 决策

- Windows 进程内提供 HTTPS/WebSocket peer endpoint，Android 主动连接。
- 数据只在明确配对的设备之间传输；每个配对关系独立认证。
- 首次配对交换设备身份、证书 SHA-256 指纹和一次性令牌，双方明确确认后保存 pair secret。
- 每台设备保存本地追加事件与 outbox，重连交换连续来源游标和缺失 ranges。
- 网络可达性由 LAN、Tailscale/WireGuard、用户 VPN 或手工端口转发提供。
- 不建设账号服务、云数据库、公共 Relay 或自动 NAT 穿透。

Windows 的监听端仅是通信角色，不构成独立后端或全局权威。协议保持对等，Windows 不能成为唯一序号分配者或写入者。

## 后果

优点：数据路径短、无需运营云服务、信任模型可由用户直接核对、离线状态由本地可靠队列处理。

代价：两台设备都处于不可达 NAT 后面时无法同步；地址变化需要已配对发现或手工配置；用户必须理解 VPN/LAN 可达性。未来若加入 Relay，需要新协议版本和应用层端到端 payload 加密评审。

## 被否决的方案

- 中心账号/云同步：超出隐私、运维和产品边界。
- 公共 Relay/NAT 穿透：超出第一版范围并改变威胁模型。
- Bluetooth 协议：配对体验可以类似，但目标网络传输不限定蓝牙。（此处否决的是"蓝牙作为主传输"；蓝牙作为 IP 不可达时的备援见 ADR 0005。）
