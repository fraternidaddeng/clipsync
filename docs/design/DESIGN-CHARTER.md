## 零、元原则

**一切以迎合你的审美为主要目标，不迁就大众需求。这是一个纯粹的私人项目。**

在此前提下，第二优先级是**易懂、符合直觉**。

> 你的原话：「不用太考虑是不是迎合大众需求，这是一个纯粹的私人项目，一切以迎合我的审美为主要目标」
> 「应当全部优先服务于我们美学的情况下，尽量做的易懂符合直觉」

**推论**：当美学与惯例冲突时，美学胜。当美学与「看不懂」冲突时，必须两者都要——不能用「这是我的审美」豁免难用。

## 一、四个关键词（总纲）

| 关键词 | 含义 | 主要实现手段 |
|---|---|---|
| **通透清新** | 能看穿、能流过，不厚重 | 低彩度、大留白、明度差而非分割线 |
| **富有层次** | 有纵深，不是一张平纸 | 五级明度阶梯 + 四档阴影 + 受光渐变 |
| **不显杂乱** | 密度高但不吵 | 一屏一个主角、色相配额、缺省即隐藏 |
| **轻量化** | 感觉上轻，也真的省 | 砍时间性装饰、拒不可移植特效 |

**这四条互相牵制。**「富有层次」推向更多视觉元素，「不显杂乱」推向更少；「通透」推向低对比，「层次」需要足够对比。**张力本身就是这个设计的难点**，尤其在设置页（10 个开关 + 约 400 字说明）这种高密度界面上。

## 三、你明确指定的

### 3.1 背景基调：灰蓝
色相锁定 245–255，彩度 ≤ 0.02。

**理由（我补充的论证，你可否决）**：这个应用装的是**别人的内容**——URL、代码、中文笔记，v2 之后还有任意截图。粉蓝渐变框住一张随机截图会很难看，灰蓝框住它是隐形的。**Chrome 必须中性到不与它无法预测的内容打架。**

### 3.2 胶片颗粒：保留，但不要太明显
> 「胶片颗粒保留是不是更好看，但是不要太明显」

- 强度：日间 **3.0%**，夜间 **4.2%**（夜间必须更强——暗部色带更明显，且暗环境下人眼对高频噪声更不敏感）
- 定位修正：**它不是设计语言的一部分，是单端的、局部的技术修补**。真实功能是**抖动**，打碎灰蓝大面积渐变的色带
- 只铺**手机应用背景**一处。卡片内部、Windows 托盘浮窗、通知、磁贴一律不铺

### 3.3 不同来源用不同颜色，带框
> 「这里消息来源是不是加个不同颜色的框比较好」「不同的来源使用不同的颜色」

- 采用「低彩度着色盒」：有背景、有边框、有色，但彩度只有状态色的 1/3
- **框（结构）是必须的**——现状裸图标与时间戳同为灰色小字，没有视觉锚点

### 3.4 框色用邻近色
> 「框的颜色选取是邻近色还是对立色比较好」→ 邻近色

设备色分配（按**配对顺序**，非哈希，允许手动改）：

| 顺位 | 色相 | 命名 |
|---|---|---|
| 1 | 195 | 青灰 |
| 2 | 215 | 水蓝 |
| 3 | 275 | 紫蓝 |
| 4 | 305 | 藕紫 |
| 5 | 335 | 灰粉 |

彩度统一 **0.03**。

**几何理由**：流动蓝（250）与召唤赭（65）相距 185°，**状态轴已经用掉了色环上唯一一对可用的对立位置**。排除绿（100–180）和红（5–32）后，剩余自由区拼不出第二对相距 180° 的位置。**对立关系是稀缺资源，已花在最需要区分的语义上：「一切正常」vs「需要你介入」。**

### 3.5 字体控制在少数几种
> 「字体选择什么，控制在几种之内」

**三个声音**，不是三种字体：

| 声音 | 字体 | 用途 |
|---|---|---|
| **Serif** | Noto Serif SC 600 / +.14em | 应用**自己**的声音。品牌名、空状态、配对仪式。全应用不超过三处 |
| **Sans** | Plus Jakarta Sans + **Noto Sans SC** | **内容**的声音。承担 95% 文字 |
| **Mono** | JetBrains Mono | **机器**的声音。时间戳、快捷键、哈希、字节数。**绝不用于中文** |

**硬性要求**：Plus Jakarta Sans 无中文字形。必须**显式指定并随包分发中文无衬线**，否则 Windows 落微软雅黑、Android 落 Noto CJK 或 OEM 魔改字体——**双端统一在占比最高的文字上直接断裂**。总计需打包 5–6 个字体文件。

### 3.6 双端美学统一
> 「双端的美学如何保持统一」

**共享「骨」，不共享「皮」**：

- **骨**（必须逐位相同）：色相关系、明度节奏、缓动曲线 `cubic-bezier(.16,1,.3,1)`、超椭圆指数 n、留白比例、状态语汇
- **皮**（各自舒服）：圆角半径（Win 8–14px / Android 16–28px）、动画时长（Win 180–220ms / Android 260–320ms）、密度

**关键约束**：**统一的地基不能是毛玻璃。** WPF 没有元素级 backdrop blur；Android 的 `setBackgroundBlurRadius` 会被 MIUI 和省电模式关掉。模糊只能是渐进增强——有则更透，无则提高不透明度，**版面一格不动**。

### 3.7 对称设计
> 「保持对称设计感觉符合直觉，会比较和谐」

已采用的对偶：
- **rail（四段状态条）**在手机状态带、Windows 标题栏、通路页三处复用同一语汇
- **缺省即本地**：两端都只给对侧来的项打标签，「无标签＝此地」是完美镜像
- **设备身份用形**：显示器字形 / 手机字形 / 无字形

已否决的对偶：**明暗分置**（PC 亮 / 手机暗）——会摧毁「同一个产品」的整体感。替代：同一套底色，手机略压明度、略提暖度（同一房间的上午十点与下午四点）。

## 四、你已认可的结构决策

### 4.1 七步向导 → 三条路线 ✅
7 个步骤不是 7 个任务，是**打通「读取」这一段的三条路线的前置条件之并集**。

| 路线 | 质量 | 代价 |
|---|---|---|
| 特权直读 · 内置特权宿主 | ●●● | 一次 adb 启动授权 |
| 日志感知 + 悬浮窗 | ●●○ | adb 授 READ_LOGS + 悬浮窗权限 |
| 悬浮窗轮询 | ●○○ | 仅悬浮窗权限，耗电有延迟 |

用户关心的是「能不能用、代价是什么」，不是 `READ_LOGS` 或 binder。

### 4.2 五个页面 → 三个位置 ✅

| 位置 | 内容 |
|---|---|
| **一屏** | 历史列表 + 顶部状态带 |
| **通路** | 四段管道，吸收了 健康 + 向导 + 配对 |
| **偏好** | 10 个开关按语义分 5 组 |

「配对」挂在通路的**网络段**下——配对的本质就是接通网络段。健康屏的 23 种状况各自挂到对应管道段，不再平铺。

## 五、由此推导的硬规则（我提出，你未反对，可修订）

### 5.1 三条铁律
1. **层次靠光，不靠框。** 深度由「明度差 + 阴影 + 高光边」制造，不由分割线和描边制造。每加一条分割线，就少一分通透。
2. **一屏之内只有一个主角。** 一个实心主按钮、一处最高彩度、一个 z2 层。「杂乱」几乎从不来自元素太多，而来自**同级元素太多**。
3. **双端共享的是骨，不是皮。** 强行让 WPF 长得像 Compose，只会两边都别扭。

### 5.2 空间层次 vs 时间装饰
**判据不是「这个界面存在多久」，而是「它是空间的还是时间的」。**

| 保留（空间性，两端可一比一移植） | 拒绝（时间性或平台独有） |
|---|---|
| 五级明度阶梯 | 22s 环境漂移 |
| 面内受光渐变 | 镜面流光（仅配对成功可考虑一次） |
| 边缘高光 | 嵌套毛玻璃 |
| 四档阴影 | 渐进式模糊 |
| 凹陷面 | 色散 / 折射 |
| 背景大渐变 | |

空间层次在 0.1 秒的界面上也成立；时间装饰要 3 秒以上才有意义。**Windows 托盘浮窗只活 3 秒，22 秒呼吸周期一个都走不完。**

### 5.3 五级明度阶梯
`底 → 凹陷 → 面 → 抬起 → 强调`

灰蓝为保持中性，明度集中在 88–99%——**可用区间只有 11 个百分点却要塞 5 级**，所以每级差值必须精确，且必须同时用渐变和阴影补足。**光比色值更能造深度。**

**夜间的阴影逻辑是反的**：抬起意味着**变亮**，不是投更深的影。只加深阴影不提亮面色，层次会完全消失。

### 5.4 彩度三档 = 三个语义层
```
底色      .015   环境
设备色    .030   标注
状态色    .090   信号
```
眼睛天然把彩度读作重要性，**状态永远赢——不需要额外规则保证优先级，物理上就成立**。

**背景的彩度永远不能超过压在它上面的文字。** 这是「花」「乱」的生理成因。

### 5.5 状态编码：一个形，五种填充
五种状态不用五种色相（那就是 color noise），改用同一形态的填充程度：

| 状态 | 视觉 | 关键判断 |
|---|---|---|
| 需要你操作 | 空 + 赭色描边 + 脉动 | **全屏唯一会伸手的** |
| 就绪 | 满填充 | 好消息不该抢注意力 |
| 降级 | 52% 半填充 | **必须一眼可辨**——特权直读通道卡死 bug 正是永久停在此态 |
| 不可用 | 灰实填充 | **陈述事实，不是错误** |
| 未探测 | 虚线轮廓 | 缺信息 ≠ 坏消息 |

**「不可用」绝不能长得像错误。** MIUI 上有几项能力永久不可用，这是常态。若画成红色，应用在主力机上永远显示成坏的，**用户会失去对所有告警的信任**。

**红色只留给 error**（写入失败、证书变更），别的一律不用。

### 5.6 核心隐喻：通路
**这个应用只有一个问题——通不通。** 其余全在回答「堵在哪」。

四条能力轴不是并列清单，是**一条管道的四段**：`本机读取 → 本机服务 → 网络 → 对端写入`，按剪贴内容的实际旅程排序（也是排障顺序）。

**「通透」在这里是字面兑现**——美学词和功能词是同一个词。应用叫「剪剪相传」，核心动作就是传递。

同时：四段中**最多一段能「伸手」**。若两段同时需操作，按管道顺序只点亮上游那段。

### 5.7 排版与几何
- **圆角嵌套定律**：`内圆角 = 外圆角 − 内边距`。半透明会放大角落几何关系，这是玻璃质感 UI 最高频的失误
- **超椭圆而非圆角**：指数 n ≈ 4–5，两端共享 n、各自选半径
- **间距只用一组数**：4 / 8 / 12 / 16 / 24 / 32 / 48。不出现 10、14、18、20
- **悬停位移只有 1px**，层次靠阴影变化传达，不靠位移幅度

### 5.8 系统表面：你几乎没有设计权
通知、QS 磁贴、托盘图标由系统绘制（MIUI 还会二次改写）。**你能控制的只有：单色图标形状、文案、动作按钮的数量与顺序。**

所以**折线标记**必须在 24dp 单色下成立——它同时是应用图标、通知图标、磁贴图标、托盘图标、dock 图标。选它的理由：6 个顶点、无闭合区域、单笔画，缩到 16px 仍可辨，深浅任务栏都成立。

**这三个表面是应用被看见最多的地方**（托盘图标 100% 时间可见，浮窗 0.1%）。

### 5.9 文案是约束，不是变量
`settings_image_sync_hint` = 「默认开启。仅 PNG/JPEG。原始字节含 EXIF。没有设备实测的图片后端不会标为可用。」（2026-08-28 随 ADR 0004 修订：产品默认由关改开，文案随事实更新——诚实文案跟随真实默认值，其余承诺不变。）

这类长说明是**隐私承诺**，删掉就是欺骗。**设计要适应诚实的文案，不是反过来。**

向导 81 条 + 配对 36 条 = 117 条，占全部 UI 文本的一半；历史只占 7%。**这个应用是诊断仪表，不是内容浏览器。**
