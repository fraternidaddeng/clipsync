「不可用」绝不能长得像错误。 MIUI 上有几项能力是永久不可用的，这是常态而非故障。若把它画成红色，应用在你的主力机上会永远显示成坏的——用户会失去对所有告警的信任。红色只留给 error，别的一律不用。
「降级」必须一眼看得出。 审计里那个 Shizuku 卡死 bug 正是永久停在降级态——UI 若把降级画得和就绪差不多，这类故障就会静默几个月。半填充与满填充的差异必须在余光里成立。

顺序即隐喻。 读取 → 服务 → 网络 → 写入，是一条剪贴内容从手机到电脑的实际路径。用户不需要理解「Shizuku binder」是什么，只需要看到管子在第几段变细了。这也顺带解决了健康屏那 23 种状况的归属——每一种都挂在某一段下面，不再是平铺的诊断列表。
这就是「通透」的字面兑现。 你要的美学关键词是能穿过去、能看见。把应用的核心状态做成一条看得见流动的管道，美学词和功能词就是同一个词，不是比喻。

把「做完 7 步」换成「选一条路」。 用户关心的从来不是 READ_LOGS 或 binder，而是「能不能用、代价是什么」。三条路线各自标注质量（左侧三档格）、代价、以及还差几项——差的那几项点进去才展开具体授权步骤。

好处：默认情况下屏幕上是 3 个选择而不是 7 个待办；已经走通的路线用户永远不需要看到其余步骤；而且这个结构诚实地反映了后端的降级链——审计里那条「Shizuku 卡死后永不降级」的 bug，在这个 UI 下会立刻暴露成「明明有可用路线却没切」。

设备身份用形，不用色一个显示器字形＝来自电脑，无字形＝本机。不花任何色彩预算——而且通知和 QS 磁贴上你根本没有颜色控制权，字形是唯一能跨这三个表面统一的编码。
色彩预算只花在状态上深蓝＝流动/就绪，赭黄＝需要你，红＝仅 error。灰蓝底上单独一点深蓝，正好是「一屏一个主角」。
状态带是折叠起来的管道四个小段直接对应上面那条管道。同一个视觉语汇在两个尺度上复用——学一次，处处认得。
「通路」的图标是折线不是齿轮、不是心跳。折线暗示"路径与转折"，与管道隐喻同源。
颗粒保留，但要察觉不到整页铺了一层——先别往下看，回想一下你刚才注意到它了吗。这就是它该有的强度：你不会看见它，但拿掉之后画面会显得"薄"。它的技术功能是打碎大面积灰蓝渐变的色带。
没有环境漂移、没有流光那两样在 3 秒可见的托盘浮窗和高密度状态界面上不解决任何问题，只是成本。通透在这里靠留白和低彩度实现。

一个字形，四种尺寸，两种极性。 折线同时是「通路」页的图标、托盘图标、通知图标和磁贴图标——它就是这个应用的标记。选它的理由：16px 下仍然可辨（只有 6 个顶点、无闭合区域）、单笔画所以描边粗细可随尺寸线性调整、且在浅色与深色任务栏上都成立。

07灰蓝的构造

彩度天花板 C ≤ 0.02，色相锁定在 245–255。切到夜间看同一套结构。

为什么用「同色相 + 彩度跃迁」，而不是另找色相。 底色是灰蓝（色相约 250，彩度 0.015），流动色用同一色相、彩度拉到 0.09——六倍跃迁，辨识度足够，却仍然是「同一片光下的东西」。这是最克制的强调方式：不引入任何新色相，杂乱从源头被掐掉。

绿色系已全部移除。青绿看似与「流动/水」同源，但在灰蓝冷底上会把整体拉向医疗仪表的廉价感，而且它引入第三个色相族——正是你反对的东西。现在全应用只有两个常驻色相：灰蓝（底与流动共用 250）、赭黄（召唤 约 65）。红是第三个，但只在真正 error 时露面。
关于灰蓝的克制。 彩度压到 0.02 以下不只是审美选择——这个应用装的是别人的内容：URL、代码、中文笔记，v2 之后还有任意截图。粉蓝渐变框住一张随机截图会很难看，灰蓝框住它是隐形的。Chrome 必须中性到不与它无法预测的内容打架。

08颗粒：怎么做到"察觉不到"且两端一致

这一页本身就铺着它。上次我说"渲成 PNG 打包"是错的，下面是真正的规格。

一、它的功能不是装饰，是抖动

灰蓝近中性色的大面积柔和过渡，在 8-bit 下必然出现色带——一圈一圈的等值线。颗粒的作用是打碎色带，让渐变看起来是连续的。这就是为什么它必须弱到看不见：一旦你注意到它，它就从抖动变成了噪点。

强度：日间 3.0%，夜间 4.2%。 夜间要更强——暗部的色带比亮部明显得多，同时人眼在暗环境下对高频噪声更不敏感。这个不对称是必须的，两边用同一个数值一定有一边不对。

二、1 纹素必须等于 1 物理像素

这是上次我漏掉的关键。 如果贴图跟随密度缩放，Android 3x 屏上一个纹素会被拉成 3×3 像素——颗粒变成糊斑，色带照样在。Windows 150% DPI 同理。

Android：放 res/drawable-nodpi/grain.png。nodpi 的语义就是「永不缩放」，1px 贴图 = 1px 屏幕。用 ShaderBrush(ImageShader(bitmap, TileMode.Repeated)) 平铺。

Windows：ImageBrush 配 TileMode="Tile"、ViewportUnits="Absolute"，Viewport 尺寸取 256 / VisualTreeHelper.GetDpi(this).DpiScaleX（DIP 值），这样它才落在 256 个物理像素上。再加 RenderOptions.SetBitmapScalingMode(el, BitmapScalingMode.NearestNeighbor) 禁止重采样。

三、一张贴图，日夜共用

别做两张 PNG。 做一张 256×256 的纯 alpha 贴图（RGB 全黑，只有 alpha 通道带噪声），然后用它当遮罩去染一层纯色：日间染黑、夜间染白。这样切主题只换一个颜色值，贴图不动。

Windows 用 OpacityMask；Compose 用 drawWithContent 配 BlendMode.DstIn，或直接给 ImageShader 套 ColorFilter.tint。本页就是这么做的——看 .grain 那条 CSS，mask-image + background-color，切日夜时只有颜色在变。

表面铺?理由
应用背景（手机全屏）铺大面积、长时间可见、有渐变——色带风险最高

所以它只出现在一个地方：手机的应用背景。 这也顺带解决了「两端一致」——Windows 端根本不用它，就不存在两端颗粒对不齐的问题。之前我把它当成双端共享的承重墙，那是想错了方向：它是单端的、局部的、技术性的修补，不是设计语言的一部分。
