五级不是四级。 我上一版只有「底 / 面」两级，凹陷面和抬起面都缺席。「凹陷」这一级尤其重要——输入框、代码块、内嵌说明框都该比底色更暗，它给出"能装东西"的暗示。只靠边框的输入框看起来像贴上去的贴纸，不像一个凹槽。
为什么灰蓝更难分层。 你原来那套高调浅色（`#bce0f8`→白）明度区间宽，随便取几个值就分得开。灰蓝为了保持中性，明度集中在 88–99% 之间——可用区间只有 11 个百分点，要塞 5 级。所以每一级的差值必须精确，不能随手取。这也是为什么必须同时用渐变和阴影来补——光比色值更能造深度。

04四档阴影怎么两端移植

这是上一轮我说"WPF 只能挂一个 DropShadowEffect"的正确解法。
档用途构成ComposeWPF
z−1 凹陷输入框、代码块、缩略图仅内阴影 自绘 drawIntoCanvas 或渐变叠层内层 Border + 上→下渐变 Background
z1 面卡片、常驻容器弱外阴影 + 顶部 1px 高光 Modifier.shadow(3.dp) + border外 Border 挂 DropShadow，内 Border 画高光
z2 抬起悬停、展开、浮窗三段外阴影 + 更强高光 Modifier.shadow(12.dp)同上，DropShadow 参数加大
强调主按钮无阴影，靠色——
关键：不要试图在一个元素上叠三个阴影。 Web 的 box-shadow 能逗号叠加，两个原生端都不能。正确做法是把三层拆到三个嵌套容器上：最外层负责外扩柔影，中间层负责 1px 边框，最内层用一条 2px 高的渐变负责顶部高光。

这样每个容器只承担一件事，两端结构完全对应。而且它比 Web 版更省——WPF 的 DropShadowEffect 只在最外层出现一次，不会重复光栅化。
夜间的阴影逻辑是反的。 暗色下抬起意味着变亮，不是投下更深的影。所以夜间版 --sf-up（#242e3b）明显亮于 --sf（#1b232e），而阴影只用来把卡片和背景隔开。如果夜间只加深阴影不提亮面色，层次会完全消失——这是暗色主题最常见的失败。切到夜间对比两版能直接看出来。

05这次没有加回来的

区分「空间层次」和「时间装饰」——前者补回，后者仍然不要。
项状态理由
明度阶梯 5 级已补回层次的主要来源，纯色值，零成本
面内受光渐变已补回薄瓷感的核心，一条线性渐变刷
边缘高光已补回给出厚度，1px Border 即可
四档阴影已补回深度的语法，拆成嵌套容器可移植
凹陷面已补回"能装东西"的直觉暗示
背景大渐变已补回给出光的方向；配合颗粒防色带

镜面流光仍不加与"安静"相斥；仅配对成功可考虑一次
嵌套毛玻璃仍不加WPF 渲染不出，两端必然不一致
渐进式模糊仍不加同上；明度渐隐已能替代
六项补回，四项仍拒。 补回的全部是静态的、空间的、两端可一比一移植的；仍拒的全部是时间性的或平台独有的。

这条界线比我上一轮画的那条准确得多：上一轮我用"这个界面存在多久"来判断，结果把静态层次也一起否了。正确的判据是"它是空间的还是时间的"——空间层次在 0.1 秒的界面上也成立，时间装饰在 3 秒的界面上才有意义。
