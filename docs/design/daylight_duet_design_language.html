晨曦对偶
Daylight Duet · Design Language v1

沿着你从「沉溪」到「晨曦花瓣」的那条路继续走。深色被否掉是对的——通透的前提是光要能穿过去，而不是被吸收。这份规范只做一件事：把你已经调出来的直觉，固化成两端都能落地的规则。

00三条铁律

如果只记住三句话，记这三句。剩下的都是它们的推论。
一 · 层次靠光，不靠框。 深度由「明度差 + 模糊 + 高光边」制造，不由分割线和描边制造。你现有的三层阴影（外扩柔影 / 1px 白环 / 内顶高光）就是一片半透薄瓷在接光的物理模型——它应该是唯一的高度语汇，只允许三档强度。每加一条分割线，就少一分通透。
二 · 一屏之内，只有一个主角。 一个实心主按钮、一处最高彩度、一个 z2 层。其余全部退成幽灵态。「杂乱」几乎从不来自元素太多，而来自同级元素太多。
三 · 双端共享的是骨，不是皮。 骨＝色相关系、明度节奏、缓动曲线、圆角性格、留白比例。皮＝模糊半径、控件形状、密度。骨必须逐位相同，皮必须各自舒服。强行让 WPF 长得像 Compose，只会两边都别扭。

01背景层次 · 四层，不多不少

悬停展开。你现在是五层（底色渐变 / 环境光斑 / 噪点 / 壳玻璃 / 卡片玻璃）——建议压到四层。
z2焦点卡片 · 仅悬停或展开时存在
z1主容器薄瓷 · 一屏一个
z0+胶片噪点 opacity .02 · 全局一张
z0环境光场 · 渐变 + 光斑，永不可交互
底色渐变与环境光斑合并为一层「环境光场」——它们在视觉上本来就不可分辨，拆成两层只增加渲染成本。
为什么是四层：人眼在单一场景里能稳定分辨的半透明深度层级约为 3–4 层。超过之后，每一层的 alpha 都必须调低才不至于糊成一片，结果是所有层都变弱，整体反而失去层次。这就是「层次感」和「层数」的悖论：层数越多，层次越弱。
卡片不要再套玻璃。 z2 用提高不透明度（.48 → .85）而不是再加一次模糊来浮起。原因有二：一是视觉上「模糊套模糊」会丢掉背景纹理，通透感反而下降；二是 WPF 根本渲染不出嵌套 backdrop blur（见 §06）——这条规则让两端天然一致。

这对色的关系值得说明。 两者色相相距约 110°——不是 180° 的正补色。正补色是最粗暴的对比，会互相「打架」产生振动感；而 110° 左右的分裂补色既有足够辨识度，又保留了共同的灰度基底，这正是它读起来「高级」而非「艳丽」的原因。而且二者明度（L≈.43 / .47）和彩度（C≈.09 / .10）几乎相等——等重，所以谁也不压过谁。这就是「对偶」而非「主次」。

彩度天花板 —— 「不杂乱」的量化定义

规则：背景的彩度永远不能超过压在它上面的文字。 一旦背景比前景更「有色」，视线就会被背景抢走，这就是「花」「乱」的生理成因。落成数字：环境层 C ≤ .04，文字 C ≈ .05–.06，点缀 C ≈ .09–.11，且点缀只允许出现在总面积 5% 以内。你现在的 --accent-warm-bg 用 8% alpha 正是这个道理的体现——把高彩度的色相稀释成低彩度的底，色相还在，彩度降下来了。
关于红绿指示灯。 你提的「PC 红 / 手机绿」这个直觉——对称的部分是对的，选色我建议换掉。三个理由：一，红色在状态灯语境里被「错误」占死了，拿它表示「这是电脑」会和真正的报错语义打架，而你确实有 --danger:#b91c1c 要用；二，红与绿明度接近，转成灰度几乎无差，这是最弱的一对辨识轴（也正好是最常见的色觉障碍轴）；三，饱和红绿会直接摧毁你花力气建立的低彩度体系——那就是你自己说的 "color noise"。而你其实已经解决了这个问题：production 稿里给 Android 来的剪贴项打的是 source-tag-warm。冷暖轴就是设备轴，它比红绿更安静、更耐看，还把红色留给了真正的错误。

机器的声音。时间戳、快捷键、哈希、字节数、设备 ID。绝不用于中文——JetBrains Mono 无中文字形，混排会掉字回退，等宽也就失去意义。

这是你当前方案里最大的一个隐患，而且它是隐形的。 Plus Jakarta Sans 没有任何中文字形。你的应用是中英双语（values/ + values-zh-rCN/），所以界面上绝大多数中文走的是系统兜底字体——Windows 落到微软雅黑，Android 落到 Noto Sans CJK 或 OEM 魔改字体。结果是：拉丁文字是你精心挑的，中文是系统随便给的，而且两端给的还不是同一个。

你想要的「双端统一」，恰恰在占比最高的那部分文字上是断的。必须显式指定并随包分发一款中文无衬线。与 Jakarta 的几何人文主义气质最搭的三个候选：Noto Sans SC（与你已用的 Noto Serif SC 同源，字重与字面率最协调，稳）、HarmonyOS Sans SC（更现代、更「仪器感」，与你的高调冷调很配）、思源黑体（最经典，略传统）。

算总账：3 个声音 × 2 套字形 = 需要显式打包 5–6 个字体文件。 别指望 fallback。

04形 · 圆角嵌套定律

这条最容易被忽略，也最容易造成「说不上来哪里怪」。拖动滑块看差别。
内 = 外 − 内边距
同心 · 两条弧线平行
内 = 外（错）
不同心 · 角落被挤压
外圆角20 / 12 → 8
公式：内圆角 = 外圆角 − 内边距。 两条弧才会同心，角落的留白才恒定。相等时内角显得过圆、被外角「挤」住；差太多时内角显得死板。这是玻璃质感 UI 里最高频的失误来源——因为半透明会把角落的几何关系放大得很明显。
超椭圆而非圆角。 两端都用 squircle（超椭圆，指数 n≈4–5），而不是标准圆角矩形。曲率连续变化，没有圆弧接直线那个二阶不连续点，视觉上更「流体」——这正好接上你 fluid_* 那几稿想要的感觉。双端共享指数 n，各自选半径：Windows 收紧（8–14px），Android 放开（16–28px）。同一种角的「性格」，不同的尺度。iOS 用的就是这个；Compose 有 RoundedPolygon，WPF 需要自绘 Geometry。
间距只用一组数：4 / 8 / 12 / 16 / 24 / 32 / 48。 不出现 10、14、18、20。约束的是「可选项数量」，不是「精度」——选项越少越难出错，节奏感自然出现。

05双端对偶 · 你问的「还能设计什么」

对称的价值不在装饰，在于它把「两台设备是一个整体」这件事变成可感知的。以下按我推荐的优先级排。
轴WindowsAndroid为什么这样分
① 色温雾霭水青花蕊粉黛 已在你稿中成立。桌面＝静止/工位/冷；手机＝贴身/掌心/暖。每条剪贴项带着它出生地的体温——扫一眼历史就知道这段来自哪一侧，不需要读标签。
② 呼吸同频同一条 22s 曲线，相位锁在挂钟时间 相位 = (unixMillis % 22000) / 22000。不需要任何网络同步，两台设备的背景光场天然同频。手机放在键盘旁边时，两块屏在一起呼吸。零成本，且只有你会发现——最适合私人项目的那种细节。
③ 状态即背景连接＝光场漂移；断开＝凝固并降彩度 用整个环境层当状态指示，而不是加一个小圆点。既删掉一个控件（轻量化），又让状态在余光里就能感知。断线时画面「静止」的那一瞬是极强的信号，但完全不吵。
④ 重力方向托盘浮窗自右下升起
同步出去的项向下淡出		列表贴底、拇指可及
同步出去的项向上淡出		 两端的「出口」朝向彼此。久而久之会形成一条心理管道：内容从这台沉下去，从那台浮上来。
⑤ 节奏180–220ms260–320ms 缓动曲线逐位相同（cubic-bezier(.16,1,.3,1)），只有时长不同。鼠标要求精准即时，手指需要动画跟手。同一个演奏者，不同的速度。
⑥ 确认通道一次视觉脉冲一次触觉轻击 两端都绝不发声。各自用最贴合自己身体的通道回执：桌面是眼睛，手机是手指。意图对称，媒介不同。
⑦ 缺省即本地只给对侧来的剪贴项打标签，本地项不打 「无标签＝此地」在两端都成立，是完美镜像的语法。同时砍掉近半数标签，直接服务于「不杂乱」。
⑧ 配对仪式二维码静区带冷→暖渐变扫描框带暖→冷渐变 手机「吞下」二维码的瞬间，两个渐变正好补成完整的一环。一生只发生一两次，正因如此值得做——这是产品唯一的仪式时刻。
不建议做的对偶：明暗分置（PC 亮 / 手机暗）。理由：它会直接摧毁「同一个产品」的整体感，而这是你的首要目标。替代方案：两端同一套高调日光底，但手机的环境光场略微压低明度、略微提高暖度——同一个房间，上午十点与下午四点。是同一处光，不是两处。

07平台能力矩阵 · 哪些能共享，哪些必须降级

这一节决定了上面所有想法哪些真能落地。以下为我的既有知识，未经联网核实（搜索限流），落地前建议实机验证标注 ⚠ 的项。

最关键的一条。 WPF 没有元素级 backdrop blur——Mica/Acrylic 由 DWM 作用于窗口自身背板，你无法让一张卡片模糊它下面的兄弟元素。所以 clipsync_production_ui.html 里「壳玻璃 + 卡片玻璃」的嵌套玻璃在 WPF 里根本不可能实现。

Android 侧看似能做（Modifier.blur，API 31+），但 Window.setBackgroundBlurRadius 会被系统「模糊开关」、省电模式和 OEM 策略直接关掉——而你的目标机是 MIUI，恰好是最激进的那一类。

所以 §01 那条「卡片不要再套玻璃，用不透明度浮起」不只是审美选择，它是唯一能让两端长得一样的选择。把模糊限定在每端唯一的最外层窗口背板上，作为渐进增强：有就更透，没有就退成不透明度更高的纯色，版面一格不动。这也顺带回答了「轻量化」——模糊是两个渲染管线里最贵的一项。
