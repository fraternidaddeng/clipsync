配对仪式 · 模态弹窗（§03）——从「通路 · 网络段」发起，不混进滚动页面。配对值得一个仪式。
为什么不做独立设置窗口：这个应用是诊断仪表，不是内容浏览器（向导 + 配对文案占全部 UI 文本的一半）。 「设置」与「状态」在这里是同一件事的两面——偏好页改「暂停捕获」，通路页的第一段立刻变灰。放在同一窗口的相邻两页， 因果关系一步可见；拆成两个窗口，就要在两个窗口之间解释因果。

四组，不是一条侧栏捕获 / 同步 / 存留 / 信任。每组一张 z1 卡片浮在 z0 底上，组内用 1px 线分行——这是唯一允许用线的地方（同卡片内的同级行）。组与组之间靠明度差，不靠框。
标题栏右侧 = 四段 rail与托盘浮窗、Android 状态带同一语汇。此刻第四段（对端写入）半填充：降级态在标题栏就看得见，不用进通路页。
开关是凹槽里的抬起钮轨道用 z−1 凹陷（sf-in + 内阴影），钮用 z2 抬起（sf-up + 边缘高光）。开 = 轨道充上流动蓝。物理隐喻与明度阶梯一致。
屏蔽进程用 chips，不用多行文本框现状是裸 TextBox 一行一个进程名。chips 让「已屏蔽哪些」一眼可数，删除是就地一击；进程名是机器的名字，用 Mono。
「重启后生效」用赭色说明，不用弹窗赭 = 需要你介入的事实。写在行内 hint 里，改完地址自然看见；不打断，不弹框。
没有「保存」按钮开关改动即生效是两端一致的行为（Android 偏好页同样无保存）。现 WPF 的「Save settings」按钮在迁移时删除。

02主窗口 · 通路与设备

PC 端的四段管道横排（宽屏读横向）：本机捕获 → 本机服务 → 网络 → 对端写入。 配对的本质是接通网络段，所以设备清单与「配对新设备」挂在网络段下，不另设设备页。

一屏一个主角本页唯一的实心按钮是「配对新设备」（流动蓝满填充）。降级段只是半填充，不抢；已撤销设备是灰的事实，不是红的错误。
设备行 = 着色盒 + 形 + Mono 元数据Pixel 8 用青灰 195（配对顺位 1），Redmi 用水蓝 215（顺位 2）。已撤销设备退到灰——彩度是活跃度。
撤销是危险动作，但不是错误状态「撤销」按钮用红色描边（error 家族唯一出场处），点击后二次确认。诚实文案写明撤销不能远程删除——这是隐私承诺，不是免责声明。
状态详情挂在段下，不平铺「省电限制」写在对端写入段的说明里，点段可展开修复动作。23 种健康状况各回各段，不再有独立健康页。

Serif 只在标题「配对新设备」「允许此设备配对？」用 Noto Serif SC 600——配对仪式是 Serif 三处配额的第三处（另两处：品牌名、空状态）。正文回到 Sans。
指纹四位一组、两行Mono 13px。人核对指纹的单位是「组」，不是字符流。两张弹窗展示同一枚指纹，左右可互证。
重复配对警告用赭，不用红现 WPF 用红色——错。换钥需要你知情，但它不是失败。赭 = 需要你介入；红只留给写入失败与证书变更。
